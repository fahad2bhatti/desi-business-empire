# Design Guide
Filename follows the founder's requested spelling: desgin.md.
Detailed screen contracts live in frontend-specification-document.md.

## Design pillars
Small beginnings, visible growth, meaningful choices, desi identity, understandable accounting, and fair optional monetization.

## Reference flow
Launch -> load/recover -> onboarding or home -> business -> stock/production/sales -> upgrade -> staff -> next stage. On resume, settle elapsed time atomically before showing the informational offline summary.

## Low-fidelity business screen
```text
[Back] Samosa Stall          [Virtual PKR balance]
[Location artwork / visible upgrade changes]
[Net profit for labeled period] [Details]
Stock: ingredients / prepared items
Production: progress and capacity
[Buy ingredients] [Serve / run business]
Next milestone: takeaway shop
[Upgrades] [Staff] [Expansion requirements]
```

## Content rules
Label net versus gross income. Explain recurring wages before hiring. Show the outcome of an upgrade before buying. Use light humor without stereotyping occupations or communities. Use fictional business/person names. No dark patterns or deceptive urgency. Display virtual currency distinctly from store purchase prices.

## Art scope
First pack: stall, takeaway, restaurant, hall, ingredients, samosa, equipment and generic staff. Use placeholders for prototype; commission/license final assets after visual approval. Maintain asset provenance. No asset or final mockup has been produced by this documentation package.

## Review checklist
Can the player identify the next goal? Are cost and benefit visible? Is locked content explained? Can text scale without hiding controls? Are failures recoverable? Is animation optional? Does every stage visibly change the business? Is there any mistaken impression of real earnings?
